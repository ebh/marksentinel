# Contributing

Thanks for considering a contribution to marksentinel.

## Setup

See the [README](README.md#development) for build/test/format/lint commands. Run format and
lint before opening a PR — CI checks both.

## Making changes

- Keep PRs focused on one change. Unrelated fixes should be their own PR.
- Add or update tests for behavior you change.
- Write commit messages that explain *why*, not just *what*.

## Pull requests

- Open against `main`.
- Describe what changed and why, and call out anything you left untested or deliberately out of scope.
- Link any related issue.

## Reporting bugs

Open an issue with steps to reproduce, what you expected, and what happened instead.
